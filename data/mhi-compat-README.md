# data/mhi-compat.json — довідник сумісності блоків MHI

**Похідні дані.** Оригінальні xlsx-файли (внутрішні дилерські документи MHI, не
публічна документація) у цьому репозиторії НЕ зберігаються — тільки цей файл,
отриманий одноразовим офлайн-розбором (ETL) двох таблиць:

| Файл-джерело | Дата версії | Пріоритет |
|---|---|---|
| `Compatibility of RAC_20260409_Customers.xlsx` | 2026-04-09 | основний, перевіряється першим |
| `compatibility of RAC_20190517.xlsx` | 2019-05-17 | архівний, лише якщо в 2026-му пари немає (з поміткою в UI) |

Розбір зроблено вручну в браузері (SheetJS), скрипт — `claude/mhi-compat-etl.js`
у цьому ж репозиторії (можна прогнати заново, якщо MHI видасть нову версію файлу:
покласти два xlsx поруч, відкрити скрипт у консолі браузера з підключеною
бібліотекою XLSX, викликати `buildAll()`, зберегти результат сюди тим самим
компактним форматом).

## Структура файлу

```jsonc
{
  "meta": { "generated_at": "...", "sources": [...] },
  "rules": [
    { "i": "SRK…ZMX-S", "o": "SRC...ZMX-S", "s": "recommended", "sr": "◎",
      "f": null, "d": true /* лише якщо є, означає ☆ — модель знімається з
      виробництва */, "src": "R2026" /* R2026 | R2019 | R2019-scm | R2019-r22 */ }
  ],
  "fact_rules": [
    { "t": "SC-BIKN2-E necessity", "i": "SRK-ZS-S", "v": "Yes", "f": null, "src": "2026" }
  ],
  "legacy_r22_rules": [ /* та сама форма, що й rules, тільки R22 on/off серія */ ]
}
```

`i`/`o` — сирий текст маркування зі стовпця/рядка таблиці (може бути wildcard/
діапазон/список ємностей — розбирається в рантаймі функцією `parseMhiCode()` в
`index.html`, тим самим алгоритмом, що й ETL). `s` — сенс статусу
(`recommended`/`conditional`/`incompatible`/`na`/`other`), `sr` — сирий символ/текст
із таблиці. `f` — текст(и) виносок `(*N)`, якщо є. Порожня клітинка і явний `-`
в обох файлах трактуються однаково як `incompatible` (MHI не дає в файлі способу
відрізнити їх — див. README ETL-скрипта).

## Використання в застосунку

Файл підвантажується (`fetch`) лише коли користувач відкриває Інфо → "Сумісність
блоків MHI" — на розмір/швидкість завантаження застосунку при старті не впливає.
Логіка пошуку — `index.html`, функції `parseMhiCode`/`matchMhiPattern`/
`lookupMhiCompat` (розділ "Сумісність блоків MHI" в коді).

## Відомі обмеження (на майбутнє)

- VRF/PAC серії (FDC, KX...) — поза межами цього довідника (тільки RAC/RAC MULTI),
  застосунок явно про це попереджає, а не мовчить "немає даних".
- Один рядок 2019-архіву (`FDEN-VD\r\n,-VF` у RAC MULTI) має нестандартний запис
  альтернативи через кому без повторення родини — розібраний як один цілий рядок
  "VD,VF", тому окремий пошук "FDTC..VF" по цьому конкретному legacy-стовпцю не
  знайде збігу. Дрібний, малоймовірний кейс у застарілих даних.
- Значення `◎` проти `〇` у файлі 2026 року офіційно не розшифровані в самій
  таблиці (є лише відсилання "Please refer to our official technical manual") —
  трактування тут (`◎`=recommended, `〇`=conditional) — робоча гіпотеза за
  конвенцією і за тим, що виноска "no official document" стоїть саме біля `〇`.
