# Залишки з 1С → наш застосунок: що налаштувати на боці 1С

**Версія 2 від 16.10.2026** — уточнено після перегляду реальної бази: УВП, звичайні форми,
клієнт-серверний варіант (SQL). Розділ «Де це розмістити» переписано: механізму БСП для запуску
обробки за розкладом у цій конфігурації немає, тому розклад дає Планувальник завдань Windows.

Доповнення до ТЗ «Автоматична відправка залишків з 1С». Тут — конкретика: адреса, код, розклад,
коди відповідей. Усе, що потрібно, — **вихідний HTTPS-запит із вашого сервера**; жодних
відкритих портів, VPN чи доступу до вашої бази з нашого боку немає.

## 1. Куди відправляти

| | |
|---|---|
| **Адреса** | `https://pwyeifgjfyymhhvzigcg.supabase.co/functions/v1/stock-sync` |
| **Метод** | `POST` |
| **Заголовок** | `Authorization: Bearer <ТОКЕН>` (токен передано окремо) |
| **Тіло запиту** | **сам файл .xlsx**, байт у байт, без JSON-обгорток, без multipart/form-data, без архівування |
| **Пробний режим** | та сама адреса з `?dry_run=1` — файл перевіряється, але **нічого не зберігається** |
| **Періодичність** | кожні **30 хвилин** |
| **Обмеження** | файл до 8 МБ (реальний звіт важить ~45 КБ) |

Жодних інших заголовків (`apikey`, `x-api-key`) не треба — лише `Authorization`.

## 2. Який саме файл

Звіт **«Анализ доступности товаров на складах»**, збережений як **.xlsx із табличного документа**
(не «плоска» вигрузка, не CSV):

- **Склади (8):** Основной Киев (Гореничи) С-А · Дополнительный Золотоноша · Дополнительный Малин ·
  Основной Одесса · Основной Харьков · Основной Львов · Основной Запорожье · Основной Днепр.
  Зайві склади в звіті не заважають — ми їх тихо ігноруємо; важливо, щоб ці 8 були.
- **Групи номенклатури (6):** PAC полупромышленные · RAC бытовые · SCM, мульти сплит ·
  FREE MATCH multi split sy… · Galactic LCAC · Galactic RAC.
- **Групування:** Склад → Номенклатура, **розгорнуте** (не згорнуті групування).
- **Показники (саме ці назви колонок):** `Залишок`, `Зарезервовано`, `До передачі`, `Вільний залишок`.
  Ми читаємо «Залишок» і «Вільний залишок», решта — для звірки.
- **Обовʼязково:** у шапці звіту рядок **«Период: на ДД.ММ.ГГГГ ЧЧ:ММ:СС»** (він там за замовчуванням).

### Три речі, на яких файл буде відхилено — врахуйте одразу

1. **Немає рядка «Период: на …»** → відповідь `422`, причина `no_timestamp`. Без часу формування ми не
   можемо відрізнити свіжий зріз від вчорашнього й не приймаємо файл узагалі.
2. **Час у цьому рядку більш ніж на 10 хвилин попереду поточного** → `timestamp_in_future`.
   Тобто на сервері 1С має бути правильний час; ми читаємо його як **київський**.
3. **Звіт помітно менший за попередній прийнятий** (менш ніж половина рядків) → `snapshot_too_small`.
   Це захист від випадкового обнулення: якщо у відборі загубились склади чи групи, ми краще
   залишимо старі дані, ніж покажемо порожні склади.

Якщо звіт не сформувався або порожній — **нічого не відправляйте**, чекайте наступного циклу.
Повторна відправка того самого файлу помилкою не є: відповідь буде `200 unchanged`.

## 3. Де це розмістити в 1С

**Перевірено в самій базі (16.10.2026):** у меню немає ні «Розсилок звітів», ні механізму БСП
«Додаткові звіти й обробки» із розкладом. Нове регламентне завдання всередині 1С означало б
зміну конфігурації (зняття з підтримки й біль при кожному оновленні), тому йдемо інакше:

> **Планувальник завдань Windows на сервері 1С** раз на 30 хвилин запускає 1С у пакетному
> режимі → вона виконує зовнішню обробку `.epf` → обробка збирає залишки й сама відправляє файл.

Конфігурація при цьому **не змінюється взагалі**: `.epf` — окремий файл поруч, не частина УВП.

**1. Користувач 1С для завдання.** Конфігуратор → *Администрирование → Пользователи* → додати
`СервисВыгрузкаОстатков`, аутентифікація 1С, довгий пароль, мінімальні права на читання
+ право запускати зовнішні обробки. «Полные права» не давати.
*Навіщо окремий:* його пароль лежатиме в завданні планувальника відкритим текстом.

**2. Обробка.** Конфігуратор → *Файл → Новый → Внешняя обработка* → *Открыть модуль объекта* →
код із розділу 4 → *Сохранить как* `C:\Sunice\ВыгрузкаОстатковSunIce.epf`.
Конфігурацію не відкривати на запис, **F7 не натискати**.

**3. Токен.** Текстовий файл `C:\Sunice\token.txt`, усередині лише сам токен. Права NTFS на папку —
тільки службовому запису й адміністраторам. (Константа тут не підходить: нова константа — це теж
зміна конфігурації.)

**4. Завдання.** На сервері `Win+R` → `taskschd.msc` → **«Створити завдання»** (не «просте»):

| Вкладка | Що виставити |
|---|---|
| Загальні | «Виконувати незалежно від реєстрації користувача» + «з найвищими правами» |
| Тригери | Щодня, **повторювати кожні 30 хвилин**, тривалість — «Нескінченно» |
| Дії | Програма: `...\bin\1cv8.exe`, аргументи — рядок нижче |
| Умови | Зняти «Запускати лише за умови живлення від мережі» |
| Параметри | Зупиняти, якщо триває понад 10 хв; «Не запускати новий екземпляр» |

```
ENTERPRISE /S"сервер\база" /N"СервисВыгрузкаОстатков" /P"пароль" /Execute"C:\Sunice\ВыгрузкаОстатковSunIce.epf" /DisableStartupMessages /DisableStartupDialogs
```

`сервер\база` — з вікна запуску 1С: вибрати базу → *Изменить* → поля «Кластер серверов»
та «Имя информационной базы».

**Повтори при збої** задаються тут же, параметрами завдання, а не кодом.

**Ліцензії.** Кожен запуск — окремий сеанс 1С на 1–2 хвилини, тобто він займає клієнтську
ліцензію. Якщо їх впритул, ставте тригер на 60 хвилин замість 30 — для залишків це прийнятно.

## 4. Код

### 4.1. Формування файлу

> **Увага:** це каркас на випадок, якщо звіт побудований на СКД і має збережений варіант.
> Остаточний код буде після того, як отримаємо з Конфігуратора точні назви регістрів
> залишків (гілка «Регистры накопления», рядки «Товары…»). Ймовірно, замість звіту візьмемо
> **власний запит до регістрів** — тоді вивантаження не залежатиме від чиїхось збережених
> налаштувань і не зламається, якщо хтось змінить варіант звіту. Приймальний бік такий «плоский»
> файл (колонки Склад · Номенклатура · Залишок · Вільний залишок) приймає від самого початку.

Каркас — підставте у двох місцях ім'я вашого звіту й варіанта налаштувань (зі збереженим відбором
по 8 складах і 6 групах):

```bsl
Функция СформироватьОтчетОстатков()

	ОтчетОбъект = Отчеты.АнализДоступностиТоваровНаСкладах.Создать();   // <-- имя отчёта в конфигурации
	Схема = ОтчетОбъект.СхемаКомпоновкиДанных;
	Настройки = Схема.ВариантыНастроек["ОстаткиДляПриложения"].Настройки; // <-- имя сохранённого варианта

	// Период берём текущий: именно он печатается строкой «Период: на ...» и читается нами.
	ЗначениеПараметра = Настройки.ПараметрыДанных.Элементы.Найти("Период");
	Если ЗначениеПараметра <> Неопределено Тогда
		ЗначениеПараметра.Значение = ТекущаяДатаСеанса();
		ЗначениеПараметра.Использование = Истина;
	КонецЕсли;

	КомпоновщикМакета = Новый КомпоновщикМакетаКомпоновкиДанных;
	МакетКомпоновки = КомпоновщикМакета.Выполнить(Схема, Настройки, , , Тип("ГенераторМакетаКомпоновкиДанных"));

	ПроцессорКомпоновки = Новый ПроцессорКомпоновкиДанных;
	ПроцессорКомпоновки.Инициализировать(МакетКомпоновки);

	ТабДок = Новый ТабличныйДокумент;
	ПроцессорВывода = Новый ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент;
	ПроцессорВывода.УстановитьДокумент(ТабДок);
	ПроцессорВывода.Вывести(ПроцессорКомпоновки);

	Возврат ТабДок;

```

### 4.2. Точка входу регламентного завдання

```bsl

	ПутьКФайлу = ПолучитьИмяВременногоФайла("xlsx");

		Файл = Новый Файл(ПутьКФайлу);
```

### 4.3. Відправка

```bsl
Процедура ОтправитьФайлОстатков(ПутьКФайлу, ПробныйЗапуск = Ложь)

	// Токен лежит в текстовом файле рядом с обработкой, в коде его нет.

	Токен = СокрЛП(ЧтениеТокена.Прочитать());
	ЧтениеТокена.Закрыть();
	Если ПустаяСтрока(Токен) Тогда
		ВызватьИсключение "Не задан токен выгрузки остатков";
	КонецЕсли;

	Соединение = Новый HTTPСоединение(
		"pwyeifgjfyymhhvzigcg.supabase.co",
		443,
		, , ,
		120,                                   // таймаут, секунд
		Новый ЗащищенноеСоединениеOpenSSL);

	Ресурс = "/functions/v1/stock-sync" + ?(ПробныйЗапуск, "?dry_run=1", "");

	Заголовки = Новый Соответствие;

			, , "Принято: " + Тело);

	ИначеЕсли Код >= 500 Тогда

		ВызватьИсключение "Сервер остатков вернул " + Код + ": " + Тело;

	Иначе
		// 401 / 413 / 422 — повторять тем же файлом бессмысленно, нужен разбор.
		ЗаписьЖурналаРегистрации("ВыгрузкаОстатков", УровеньЖурналаРегистрации.Ошибка,

```

## 5. Порядок запуску

1. **Пробний запуск:** викликати `ВыгрузитьОстаткиВПриложение(Истина)` один раз вручну
   (це додасть `?dry_run=1`). **Скопіюйте й надішліть нам текст відповіді** — у ньому немає
   нічого секретного, зате видно, як саме ми прочитали ваш звіт.
   Для орієнтира, так виглядає правильна відповідь на файлі, який ми вже перевіряли:
   `"ok":true, "format":"report", "received":1227, "accepted":1204, "ignored":23, "errors":0`
   і розбивка по складах.
2. Якщо `200` — увімкнути завдання планувальника кожні 30 хв (уже без `dry_run`).
   Результат перевіряти так: у 1С *Сервис → Журнал реєстрації*, відбір за коментарем `ВыгрузкаОстатков`.
3. Через день разом звіряємо кілька позицій з екраном 1С.

## 6. Коди відповідей

| Код | Тіло | Що це | Що робити |
|---|---|---|---|
| `200` | `"status":"ok"` | зріз прийнято й записано | нічого |
| `200` | `"status":"unchanged"` | файл ідентичний попередньому | нічого, це норма |
| `200` | `"dry_run":true` | пробна перевірка | надіслати нам текст відповіді |
| `401` | `unauthorized` | токен не той або немає заголовка | звірити токен |
| `413` | `file_too_large` | файл понад 8 МБ | звірити відбір — там явно зайве |
| `422` | `no_timestamp` | немає рядка «Период: на …» | увімкнути вивід періоду в шапці |
| `422` | `timestamp_in_future` | час звіту попереду нашого понад 10 хв | перевірити час на сервері 1С |
| `422` | `older_than_applied` | надіслано старіший файл, ніж уже прийнятий | не слати збережені старі файли |
| `422` | `snapshot_too_small` | рядків менше половини попереднього | перевірити відбір складів/груп |
| `422` | `checksum_mismatch` | підсумки складів у звіті не збігаються із сумою рядків | змінився вигляд звіту — напишіть нам |
| `400` | `parse_error` | файл не розібрався | надішліть нам цей файл і текст відповіді |
| `5xx` | — | тимчасова проблема на нашому боці | повтор через 5 і 15 хв |

## 7. Що робити не треба

- Не архівувати файл і не кодувати в base64 — тіло запиту це **сам .xlsx**.
- Не загортати в JSON і не слати як `multipart/form-data` з полем `file`.
- Не слати порожній звіт «щоб не пропустити цикл» — краще пропустити цикл.
- Не зберігати токен у коді обробки, у листуванні чи в налаштуваннях, доступних усім користувачам.
- Не створювати регламентне завдання всередині конфігурації: це зняття УВП з підтримки заради
  того, що планувальник Windows робить безкоштовно.
- Не міняти склад колонок і групувань у звіті без попередження — ми звіряємо контрольні суми
  й такий файл відхилимо цілком свідомо.
