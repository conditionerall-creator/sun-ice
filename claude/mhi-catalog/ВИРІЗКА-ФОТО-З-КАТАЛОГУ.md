# Як вирізати фото виробу з PDF-каталогу (спосіб, яким зроблено SRK-ZSPR-S і решту груп)

> Створено 2026-10-19. Узгоджено з власником: фото групи в прайсі — **вирізане, без білої підложки**,
> **лише з каталогів і сайту `galactic.ua`**, нічого не вигадувати й не домальовувати.
> Код: `claude/mhi-catalog/build_group_images.py`. Результат: `tile-images/mhi-groups/*.webp` + `_source.json`.

## Коли цей спосіб годиться
Зображення в PDF лежить **на чисто білому фоні** (так у MHI) або вже має **власну прозорість** (так у Galactic).
Не годиться, якщо виріб знятий на тлі інтер'єру/стіни (напр. FDE на стор. 126 і FDUM на стор. 114 каталогу MHI):
маска «білого» від краю таке не вирізає. Тоді шукати **чистий знімок того ж виробу** на іншій сторінці
(так для FDE взято знімок із мультисистем, стор. 57 — той самий FDE-VH).

## Крок 1. Знайти фото очима, а не за номером
```
python claude/mhi-catalog/contact_sheet.py <каталог.pdf> <перша> <остання> аркуш.png 6 60
```
Аркуш показує всі вбудовані зображення сторінок із підписом `p<сторінка> x<xref> <розмір>`. Обираєш виріб —
записуєш сторінку й xref. Темні плями без виробу — це **тіні** (окремі картинки з маскою), їх не брати.
Піктограми, пульти, фони-«кімнати» теж не брати. На сторінці серії головне фото виробу — найбільше чисте
зображення біля заголовка.

## Крок 2. Додати рядок у `PHOTOS` скрипта
`('імя-файлу', 'mhi' | 'gal' | 'site', сторінка, xref, 'що це')`. Для картинки з сайту:
`('імя', 'site', 'файл.jpg', None, 'що це', (x0, y0, x1, y1) рамка обрізання, 'адреса джерела')`, а сам файл
покласти в `claude/mhi-catalog/site-src/`. **Один виріб — один файл**: однакові вироби в спліті, мульти й
напівпромі беруть те саме фото (касета FDTC, канальний FDUM, стельовий FDE; настінні ZSX/ZR/ZS, SRF, SRR).
Запуск тільки нових: `python claude/mhi-catalog/build_group_images.py --only імя1,імя2`.

## Що робить скрипт (алгоритм вирізки — суть способу)
1. Бере **вбудоване** зображення з PDF (`extract_image` за xref), не рендер сторінки. CMYK → RGB.
2. Якщо в PDF у зображення є своя маска (`smask`) — **використовує її як є** (Galactic).
3. Інакше будує маску **з самого зображення** (`cutout()`):
   - «майже біле» (`255 − min(R,G,B) ≤ 4`) — кандидат у тло;
   - тлом вважається лише те біле, що **зв'язане з краєм кадру** (заливка від краю). Біле всередині виробу
     (блік, світла панель) лишається виробом; дірки всередині заповнюються;
   - дрібні «бризки» шуму знімаються відкриттям, лишається **найбільший об'єкт** — сам блок;
   - край стискається на 1 px і розмивається (σ = 0,9), альфа × 1,15 — **без білого ореолу** на кольоровому тлі.
4. Обрізає по контуру, зменшує до **ширини 280 px** (на картці ~120 CSS px, ×2 для Retina).
5. Зберігає **WebP з прозорістю** (~3–15 КБ) і пише в `_source.json`: каталог, сторінка, xref (або URL), розмір,
   звідки маска.

## Крок 3. Підключити до групи
Таблиця `CG_PHOTOS` у `js/04a-catalog-groups.js`: `розділ → назва групи з прайсу → імя-файлу`. Назва групи —
та сама, що в `CG_TITLES`. Тест `groups.test.mjs` перевіряє, що група існує, файл є, а в `_source.json` записано,
звідки він. **Адреса картинки в шапці має `?v=APP_BUILD`**: service worker віддає картинки з кешу за точною
адресою, без версії телефон показував би стару картинку після заміни файлу.

## Як перевірити результат
Склеїти готові файли на **кольоровому** тлі (тло шапки групи) і подивитись очима: ореол по краю, відрізані
краї, залишки сусіднього блока (для композицій із сайту). Біле на світлому тлі потребує **контактної тіні**
(`filter: drop-shadow(0 3px 4px rgba(40,30,20,.22))` — по формі блока), інакше край губиться.

## Пастки, на які вже наступили
- `pymupdf` 2.x на Python 3.14 падає в segfault при імпорті — ставити `pymupdf<2` (1.x).
- Прозорий WebP тримає тільки сучасні браузери — для PWA це ок; JPEG для цього не годиться.
- Зображення з сайту — **композиції** (внутрішній блок + зовнішній + пульт): беремо рамкою лише потрібну
  частину, потім ту саму вирізку. Перевіряти, що сусідній блок не залазить у рамку.
- Мульти Galactic H-W / H-S і серія Orient у каталозі відсутні — їхні фото з `galactic.ua` (див. `_source.json`).
